# BioGuider基准测试方法论

## 1. 为什么需要这个基准测试

大语言模型已经具备直接修改科学文档的能力，但"输出了修订版本"与"修订是正确的"之间存在一道重要鸿沟：我们如何知道模型修的是对的，而不是把本来正确的内容改错，或遗漏了真正的错误？

传统评估方法无法回答这个问题。Rubric 评分衡量的是文档的绝对质量，无法区分"模型把参数名改对了"和"模型把正确的参数名改错了"。人工评估准确但成本高昂，难以在跨模型、跨错误类别的系统性比较中保持一致性。

本基准测试借鉴了软件工程中**变异测试（mutation testing）**的设计思想：向测试对象注入已知变异，再量化检测能力。我们将这一思路迁移到文档领域：向真实的生物信息学文档注入已知类型、已知位置的错误，让模型修复，再用精确率（precision）和召回率（recall）定量衡量修复能力。关键优势在于**可控性**——注入什么、注入多少、注入在哪，全部在实验者掌控之中，任何人均可用相同参数重现相同的损坏文档，支持跨模型、跨 prompt 策略的公平比较。

## 2. 错误注入设计

### 2.1 错误类别体系

基准测试共设计了 **36 个错误类别**，划分为三个层级：

**CONTENT 类（22 个）**：涵盖科学准确性相关的错误，包括基因名大小写错误、物种名替换、基因组版本不匹配、标准化方法混淆、统计检验名称替换、参数默认值错误、数值单位颠倒、文件格式误标等。这类错误的共同特征是：如果被读者忽视，可能导致实验设计错误或分析结论偏差。例如，将 `logNormalize` 误改为 `CLR`，或将 `UMAP` 降维误标为 `tSNE`，会直接误导初学者对方法的理解。

**HYGIENE 类（11 个）**：涵盖格式与可读性相关的错误，包括拼写错误、Markdown 结构破坏、行内代码标记缺失、超链接损坏、重复段落、章节标题异常等。这类错误影响文档的可读性，但不直接危害科学理解——读者通常能推断出正确的含义，即便格式存在问题。

**UNSCORABLE 类（3 个）**：包括函数锚点（function）、代码注释拼写（comment_typo）和代码围栏语言标签（code_lang_tag）。这三类错误在结构上与代码区域紧密耦合，无法通过纯文本 prose 修复，也无法公平地评估修复质量，因此明确排除在评分体系之外。

这一分层体现了一个核心判断：**CONTENT 错误的修复价值高于 HYGIENE 错误**，因为前者事关科学正确性，后者事关呈现质量。在分析结果时，这两类错误的 F1 分数被分别汇报，支持差异化解读。

### 2.2 Prose-Only 注入原则

所有错误仅注入文档的**散文区域（prose region）**，代码围栏（fenced code block）内的内容不做任何修改。这一设计决策有两层动机：

第一，代码块是文档的**权威来源**。在生物信息学教程中，R 或 Python 代码片段代表了真实可运行的操作，它们本身即是正确答案。如果向代码块中注入错误，再要求模型修复，相当于要求模型"猜测原始意图"，而不是"依据权威更正 prose"。这不是在测量文档修复能力，而是在测量代码逆向工程能力。

第二，不同模型对"不修改代码块"这一指令的遵从程度存在差异。如果代码块中存在注入错误，遵守指令的模型会因为不敢修改而丢分，不遵守指令的模型反而可能因为改动代码而得分——这会引入与代码修改行为强相关的系统性偏差，使得评估结果无法反映真实的文档修复能力。

散文区域的边界通过对文档结构的静态分析确定：代码围栏、YAML frontmatter、以及其他结构性标记所包围的区域均不列入注入范围。

### 2.3 确定性注入

为了支持跨模型的公平比较，注入过程被设计为**完全确定性的**：给定相同的文档和相同的错误数量参数，每次注入的结果逐字节完全一致。这意味着参与比较的所有模型处理的是完全相同的损坏文档，任何性能差异均来自模型本身的修复能力，而非来自随机的注入变化。

在实际执行中，错误注入清单（injection manifest）作为元数据与损坏文档一同保存，记录每处注入的类别、原始内容、替换内容，以及在文档中的位置范围。这份清单在后续评估阶段作为 ground truth 使用。

### 2.4 注入规模

基准测试覆盖 **9 个错误水平**（5、10、20、40、60、100、150、200、300 个错误），以测试模型在低密度错误（局部修改任务）和高密度错误（近乎全文重写任务）下的表现差异。每个错误水平下，错误按类别比例分配，确保各类别的相对代表性保持稳定。

## 3. 评价指标

### 3.1 Precision、Recall 与 F1

单纯的修复率（fix rate，即"修好了多少错误 / 注入了多少错误"）是一个不完整的指标。一个将整篇文档重写为空内容的模型，理论上消除了所有注入错误，fix rate 为 1.0，但显然这不是我们想要的修复行为。

因此，评估框架采用信息检索领域的经典指标体系：

- **Precision（精确率）**：模型实施的所有改动中，有多少是真正针对注入错误的修复，而非对原本正确内容的干扰性改动。
- **Recall（召回率）**：注入的所有错误中，有多少被模型成功识别并修正。
- **F1**：Precision 和 Recall 的调和平均数，综合衡量修复质量。F1 = 2 × P × R / (P + R)。

这三个指标共同约束了模型行为：一个修复准确但不完整的模型 Recall 低；一个"见什么改什么"却常改错的模型 Precision 低；只有在正确位置做正确修复的模型才能同时获得高 Precision 和高 Recall。

### 3.2 可评分子集（Scorable Subset）

正式汇报的 F1 指标基于**可评分子集**，即排除 3 个 UNSCORABLE 类别后的 33 个类别。这一选择确保分母的一致性：UNSCORABLE 类别的错误无法被公平检测，将其纳入只会稀释真实信号。

在汇报格式上，scorable F1（整体）、CONTENT F1 和 HYGIENE F1 分别独立报告，以支持对不同维度修复能力的差异化分析。

### 3.3 两层误报检测（False Positive Detection）

误报（false positive，FP）在本框架中指模型对**未注入位置**做出的改动——即模型改动了本来正确的内容。评估系统采用两层机制识别此类行为：

**硬误报（Hard FP）**：模型的改动落在受保护区域（代码围栏、YAML frontmatter、章节锚点）。此类改动违反了基准测试的核心规则，通过将改动位置与受保护区域边界做确定性比对来检测。

**软误报（Soft FP）**：模型的改动落在散文区域，但该位置并非注入错误所在。这类"附带损伤"（collateral damage）通过行级 diff 检测：将模型输出与原始（未损坏）文档逐行比对，找出不属于任何注入错误的改动行。软误报的存在会降低 Precision 值。

两层 FP 检测共同构成了对模型"修改克制性"的量化评估——在修好注入错误的同时，是否也在不该动的地方留下了痕迹。

## 4. 模型选择实验（E001）

### 4.1 实验设置

第一阶段实验（E001）的目标是在多个主流 LLM 之间进行横向比较，确定后续实验使用的基准模型。实验涵盖 **5 个模型**：2 个闭源商业模型（GPT-4o、GPT-5.4）、1 个闭源专有模型（Kimi-K2.5）、以及 2 个开源模型（GLM-5、GPT-OSS-120B）。

所有模型通过同一个 LiteLLM 代理路由调用，消除了因 API 端点、网络延迟、认证机制不同而引入的基础设施差异。测试语料为 **10 篇 Seurat 教程文档**（涵盖差异表达、细胞周期、降维、多模态整合、空间转录组等主题），在 9 个错误水平下逐一测试，共 450 次 LLM 调用。所有模型使用相同的 BioGuider 结构化 prompt，处理完全相同的确定性损坏文档。

### 4.2 主要发现

实验揭示了一个清晰的规律：**所有模型在 CONTENT 类指标上高度一致**，F1 均集中在 0.92 附近，差异不超过 1 个百分点。基因名、物种名、统计方法这类有明确科学标准的内容，对主流 LLM 而言已不构成挑战。

**HYGIENE 类是区分模型能力的关键维度**。最优模型（GPT-4o，F1 = 0.660）与最差模型（GPT-OSS，F1 = 0.604）之间相差约 5.6 个百分点，格式修复需要对文档整体结构有更强的上下文感知。整体 scorable F1 排名为：GPT-4o（0.753）> Kimi-K2.5（0.740）> GLM-5（0.719）> GPT-5.4（0.715）> GPT-OSS（0.710）。所有模型随错误水平升高呈单调下降，但相对排名在全部 9 个错误水平上保持稳定，表明差异是系统性的。

### 4.3 模型选择依据

GPT-4o 在综合 F1、HYGIENE 表现和稳定性三个维度上均为最优，因此被选为后续实验的参照模型。开源模型（GPT-OSS）在成本和速度上有优势，且 F1 差距在 4.5 个百分点以内，在对成本敏感的应用场景中可作为替代选项。

## 5. Prompt 技能对比实验（E002/E003）

### 5.1 实验动机

BioGuider 的核心主张是：**领域知识结构化的 prompt 能够提升 LLM 在生物信息学文档修复任务上的表现**，优于仅告知评估标准的通用 prompt。为验证这一主张，E002/E003 实验专门设计了技能对比场景。

这里的"技能"（skill）指的不是模型能力本身，而是 prompt 策略：同一个模型，给它不同的指令框架，是否会产生可测量的修复质量差异？这个问题的答案直接关系到 BioGuider 作为一个 prompt 工程产品的核心价值。

### 5.2 两种 Prompt 策略

**BioGuider Prompt（技能 1）**：结构化的领域专用指令，包含四个评估维度（科学准确性、Markdown 格式、prose 与代码的一致性、内容完整性），以及关键的操作原则：将代码块视为权威参考，prose 的修改应以匹配代码为准则。这一 prompt 体现了生物信息学文档的领域知识——代码先于文字，文字的作用是解释代码。

**通用 Prompt（技能 2）**：仅陈述评估标准，不提供结构化指导。措辞刻意保持通用，不包含任何领域特定术语，不限定修改策略。这代表了一种"告知目标但不告知方法"的 prompt 风格，是实验的对照条件。

两种 prompt 策略使用完全相同的模型、完全相同的损坏文档（由确定性注入保证），评估也使用相同的评分框架。唯一的变量是 prompt 策略。

### 5.3 对比设计的价值

这一设计有意剥离了"AI 是否能修文档"这一问题，专注于测量"领域知识指导是否有增量价值"。若两种 prompt 表现相当，BioGuider 的价值在于系统集成（RAG、结构化工作流）而非 prompt 策略本身；若 BioGuider Prompt 显著更优，则验证了结构化领域知识的独立贡献。完整的矩阵实验（E003）计划在 5 篇文档、3 个错误水平上运行以获取统计可靠的结论。

## 6. 局限性

任何基准测试都有其边界条件，坦诚地陈述这些限制对于评估者判断结论的适用范围至关重要。

**文档族单一性。** 所有实验使用 Seurat（单细胞 RNA 测序分析）的 10 篇 vignette 作为测试语料。Seurat 的文档风格高度统一，代码密度高，散文结构规范。这与其他领域的生物信息学文档（例如基因组组装工具、结构生物信息学软件、机器学习框架的文档）可能存在显著差异。当前结论的外部效度（generalizability）有待在更广泛的文档族上验证。

**注入错误的代表性。** 基准测试注入的 36 类错误由研究团队根据领域知识手工设计，未必能完整覆盖真实 LLM 在生成生物信息学文档时的错误分布。特别是，某些 LLM 特有的错误模式——例如幻觉出不存在的参数名称，或混淆两个相似工具的接口——在注入清单中代表性可能不足。

**prose-code 一致性盲区。** Prose-only 注入策略虽然保证了公平比较，但也排除了一类重要的文档质量问题：散文描述与代码实现之间的不一致。尽管 CONTENT 类别中包含了若干 prose-code 一致性相关的错误类型，但这类问题的系统性覆盖尚不完整。

**F1 的等权假设。** 当前 F1 计算将所有可评分类别的 TP/FP/FN 等权处理，隐含地假设修复一个拼写错误与修复一个物种名替换错误具有相同的价值。这与实际的下游伤害并不对等——CONTENT 类错误的科学危害通常高于 HYGIENE 类错误。未来可以考虑引入基于错误类别危害程度的加权 F1，但加权系数的确定本身就需要领域专家共识，不在本研究范围内。

**单一评估器。** 基准测试的 fix 判断由单一自动评估器执行，该评估器基于 LLM 调用。当前框架中不包含人工标注者间一致性（inter-rater agreement）的验证，也未引入第二个独立评估器进行交叉核实。评估器本身可能对某些错误类别（特别是语义较模糊的 HYGIENE 类）产生系统性误判，这一风险在解读结果时需保持意识。
